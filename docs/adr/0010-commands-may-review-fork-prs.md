# Commands may review fork PRs, maintainers only

ADR-0004 keeps `pull_request` runs on forks to the job summary, because the token is read-only there. The `issue_comment` trigger runs from the base branch with secrets and a write token, so a Command can give a fork PR a full Review with a sticky Summary and Inline comments. We allow it, but only when the commenter is an owner, member or collaborator, and PR code is only ever read as text, never executed (the rule ADR-0004 set for any `pull_request_target`-style path). Anyone else's Command is ignored without a reply, so strangers cannot spend the maintainer's free-tier quota. Rejected: leaving fork PRs summary-only (maintainers would have no way to get a real review of outside contributions), and letting anyone invoke Commands.
